> 交付一个 `agent.py`：按下按钮后串起"定位 + 识图 → 生成讲解词 → 播报"的完整状态机。你是**唯一调用其他三个模块的人**，所以接口契约由你起草初稿（D1 全员过稿、负责人冻结）。你是"逻辑型"模块，工作量在状态机和提示词打磨上，是长期迭代项。

## 技术栈（敲定版）

| 层 | 选型 | 说明 |
|---|---|---|
| 状态机 | Python（idle → 并行采集 → 生成 → 播报 → idle） | 显式状态枚举，禁止隐式跳变 |
| 并发 | asyncio（或线程池） | 定位与识图**并行**发起，总延迟 = 两者较慢者 |
| 讲解文案 LLM | DashScope qwen-plus 级文本模型 | 输入位置+视觉素材+导游人设，输出口语化讲解词 |
| 按钮监听 | gpiozero（GPIO 事件回调） | 含防抖（≥300ms）与播报中打断 |
| 日志 | 全链路结构化日志（每次触发一条：时间/位置/场景/文案/耗时） | 答辩展示数据用 |

## 自测方法（不依赖其他模块）

- Mock 模式：`python test_agent.py --mock`，内置假定位/假识图数据，验证状态机流转与文案生成。
- 降级用例 1：定位失败（GPS 无星+无信标）→ 文案只基于视觉，不报错。
- 降级用例 2：识图失败 → 文案只基于位置 POI。
- 降级用例 3：双失败 → 播报固定话术："我没太看清，换个角度再按一次试试？"

## 边界与注意

- 你只编排，不实现：定位怎么读、图怎么识、声音怎么出，都是别人的模块，你只调接口。
- 但**降级策略是你的责任**：任何一个模块返回失败，主链路都不能崩，这是评委最可能故意刁难的地方（比如断你的网）。
