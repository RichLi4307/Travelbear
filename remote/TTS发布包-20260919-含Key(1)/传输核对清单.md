## 二、到 Pi 上后，四条命令确认没传漏

**这个 zip 解包后就是最终目录结构**，不用再搬文件：

```bash
# ① 解包到部署目录（得到 /home/pi/robot/tts 与 /home/pi/robot/文件清单.sha256）
mkdir -p /home/pi/robot && cd /home/pi/robot
unzip -o ~/TTS发布包-20260919-含Key.zip

# ② 完整性校验：应逐行输出 OK，共 19 条（本清单自身不参与校验）
sha256sum -c 文件清单.sha256

# ③ 文件数对照：tts/ 下应是 17 个（含 .env；不含 .tts_cache / __pycache__）
find tts -maxdepth 1 -type f | wc -l

# ④ 直接跑自检：环境没配好会明确报出来，不会静默
cd tts && ./selftest.sh
```

> ② 若有 `FAILED`，是传输中文件损坏或缺失 —— 重传那一个文件即可。
> ④ 若报 `\r': command not found`，是换行符问题：`sed -i 's/\r$//' *.sh`。

> 若你是直接 `scp -r` 目录而没用 zip，跳过 ①，改在源目录 `发布包/` 下执行 ②。

## 三、还要手工准备的

| ✅ | 项目 | 怎么弄 |
|---|---|---|
| ☐ | **`.env` 的位置** | 包里已带，但必须落在 `/home/pi/robot/tts/.env`（与 `tts.py` 同级）。若你手工搬过目录，检查一下别放到上一级 —— 放错会表现成「Key 填了却说没配」 |
| ☐ | **`.env` 权限** | `chmod 600 .env`（zip 里已写 0600，个别解包工具会丢） |
| ☐ | **`TTS_ALSA_DEVICE`**（可留空） | 留空则自动探测。若没声音：Pi 上 `aplay -l` 拿 card 名 → `plughw:CARD=<名字>,DEV=0`（**用名字不用编号**），填进 `.env` |
| ☐ | **`TTS_CACHE_DIR`** | 包里已填 `/home/pi/robot/tts/.tts_cache`；**必须是绝对路径** |
| ☐ | **系统包 `alsa-utils`** | `sudo apt install -y alsa-utils`（提供 `aplay`，唯一系统依赖） |
| ☐ | **audio 组** | `sudo usermod -aG audio pi`，然后**重新登录** |

## 四、几个容易踩的点

| 现象 | 原因 | 处理 |
|---|---|---|
| 提示没配 Key，但 `.env` 里明明有 | `.env` 放错位置（放到上一级了） | 移到与 `tts.py` 同级：`tts/.env` |
| 提示没配 Key，位置也对 | `.env` 带 BOM，第一个键名多了不可见字符 | `sed -i '1s/^\xEF\xBB\xBF//' .env`，或重新解包（脚本生成时已按无 BOM 处理） |
| `./selftest.sh` 报 `\r': command not found` | Windows 换行符 CRLF | `sed -i 's/\r$//' *.sh` |
| `./selftest.sh` 报 `Permission denied` | 解包工具丢了可执行位 | `chmod +x selftest.sh`（zip 里已写入 755，但个别工具会丢） |
| 一切正常但没声音 | `TTS_ALSA_DEVICE` 写成 `hw:` 而非 `plughw:` | 改成 `plughw:CARD=<名>,DEV=0` |
| 重启后预热失效 | `TTS_CACHE_DIR` 写了相对路径 | 改成绝对路径 |
| 提示 `Permission denied`（音频） | 不在 audio 组 | `sudo usermod -aG audio pi` + 重新登录 |

## 五、这个包怎么来的

由项目根 `导出给树莓派.py` **白名单导出**，不是手工挑的：
只放明确需要的文件，缓存 / 开发期探针一律不带。
`.env` 按团队决定**随包带上**：内容由本机 `tts/.env` 生成为树莓派版本（保留 Key，缓存目录改为绝对路径）。
压缩包：`TTS发布包-20260919-含Key.zip`（**解包后即为最终部署结构**，不含顶层目录）
