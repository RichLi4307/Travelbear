# 烧入树莓派清单（TTS 模块视角）

> 面向：zcm（只负责 TTS 模块）
> 结论先给：**"烧录"这件事主体不是你**。你只需要拷一个 `tts/` 目录进去 + 补 1 个环境变量。
> 全部系统依赖只有一个 `alsa-utils`，**不需要 pip install 任何东西**。
> **API Key 已随包带上**（见第 2 节末），所以"配环境"这一步只剩音频设备名要上机拿。

---

## 0. 先把"烧入"这个词拆开

日常说的"烧进树莓派"其实是两件完全不同的事，混在一起容易以为自己要干很多活：

| 阶段 | 做什么 | 归谁 | 你要动手吗 |
|---|---|---|---|
| **① 烧录系统** | 把 Raspberry Pi OS 镜像写进 SD 卡（Raspberry Pi Imager） | **李鑫**（硬件整合 + 树莓派运维） | ❌ 不用。他烧卡时会顺手配好 SSH 和 WiFi |
| **② 系统准备** | 装系统包、开 SSH、加用户组 | **李鑫** | ❌ 不用，但要向他提需求（见第 1 节） |
| **③ 拷模块** | `tts/` 目录 → `/home/pi/robot/tts` | **你** | ✅ 用导出脚本，一条 unzip |
| **④ 配环境变量** | `.env` 已在包里；只剩音频设备名要**上机**填（见第 5 节） | **你** | ✅ 上机后一条命令 |
| **⑤ 验证出声** | 跑自检 + 真播一句 | **你** | ✅ 一键脚本 |
| **⑥ 接开机自启** | systemd 服务 | **李鑫** | 你只提供模板 `tts.service` |

**所以：SD 卡烧录、系统安装这两步你完全不用碰。** 你的事从第 ③ 步开始。

> ⚠️ 但有个前提：**第 ③ 步之前你得能连上 Pi**。
> 现在的状态是「宿舍区无可用 IPv6 + Pi 域名只有 AAAA 记录」→ 你**连不上**。
> 这条卡在李鑫那边（需要 IPv4 通道 / 隧道），不解决的话第 ③-⑤ 步都做不了。
> 详见 `今晚会议用-对接清单与待办.md` 的 C 组。

## 1. 要请李鑫确认/提供的（系统侧）

| # | 事项 | 为什么 |
|---|---|---|
| 1 | **系统版本**：Raspberry Pi OS Bookworm（推荐）或更新 | 我们要 Python ≥ 3.8；Bullseye 是 3.9 也能跑。Bookworm 是 3.11 |

## 2. 生成要拷的包（你的一条命令）

双击项目根的 **`导出给树莓派.bat`**，或：

```bash
python 导出给树莓派.py
```

会产出两样，**推荐直接用 zip**：

| 产出 | 用途 |
|---|---|
| **`TTS发布包-YYYYMMDD-含Key.zip`**（项目根） | 拷 U 盘 / 发聊天都用它。**解包后就是最终部署结构**，不用再搬文件 |
| `发布包/`（目录） | 同内容；给"直接 scp 目录"用，也方便你打开检查 |

```
发布包/                        ← zip 解包后也是这个样子
    tts/                       ← 整个目录就是 Pi 上的 /home/pi/robot/tts
        .env                   ← ★ API Key 已在这里，解包即用（树莓派版）
    .env.example               ← 不含 Key 的模板，备用
    烧入树莓派清单.md           ← 本文件
    传输核对清单.md             ← ★ 到 Pi 上照着逐条打勾，防遗漏
    文件清单.sha256             ← ★ 传输完整性校验（sha256sum -c）
```

### 怎么传（三选一）

```bash
# ① 推荐：解包即部署（zip 已传到 Pi 后执行）
mkdir -p /home/pi/robot && cd /home/pi/robot
unzip -o ~/TTS发布包-20260919-含Key.zip
sha256sum -c 文件清单.sha256           # 应逐行 OK，共 19 条
find tts -maxdepth 1 -type f | wc -l   # 应输出 17（含 .env）
chmod 600 tts/.env                     # zip 里已写 0600，个别工具会丢

# ② scp 传目录（只传 tts，校验清单不跟着走）
scp -r 发布包/tts pi@<地址>:/home/pi/robot/

# ③ U 盘 / FTP —— 换行符与执行权限最容易被弄坏，见第 7 节
```

> ### 关于包里的 API Key
> 按团队决定，**`.env` 随包带上**（含 `MIMO_API_KEY`），目的是"少一步人工操作、少一处配错"。
> 脚本做了三件事保证不出岔子：① 生成的是**树莓派版** `.env`（Key + 绝对路径缓存目录）；
> ② zip 名带 `-含Key` 后缀，和临时导出的不带 Key 的包一眼可分；
> ③ `.env` 在 zip 内的权限位写 **0600**。
>
> 两条注意事项：
> - 这个包**只在组内流转**。要发给组外的人，用 `python 导出给树莓派.py --no-env` 重新导一份。
> - `tts/.gitignore` 已经忽略 `.env`，**但 zip 本身不受它管辖** —— 别把 `发布包/` 或 zip 提交进 git 仓库。

## 3. 拷进去放哪（注意 `.env` 的位置）

```
/home/pi/robot/            ← 部署根目录（待李鑫确认）
├── 文件清单.sha256         ← 校验用，放着不用管
└── tts/                   ← 发布包里的 tts 目录整个放进来
    ├── tts.py
    ├── selftest.sh
    ├── .env               ← ★ 必须在这里（与 tts.py 同级），不是上一级！
    └── .tts_cache/        ← 首次预热时自动创建
```

> ### ★ 为什么 `.env` 必须在 `tts/` 里
> 代码按「**脚本所在目录**」查找 `.env`（`os.path.dirname(__file__)`）。
> 放到上一级 `/home/pi/robot/.env` 会读不到，表现是"Key 明明填了却说没配"。
> 所以 `tts.service` 里的 `EnvironmentFile=` 也指向 `/home/pi/robot/tts/.env`，**单一真源**，
> 不在这里再写一遍同名变量（systemd 的 `Environment=` 优先级更高，会把 `.env` 的值盖掉）。

> 部署根目录**还没定**（待李鑫给）。上面按 `tts.service` 模板里的 `/home/pi/robot/` 写，
> 定了之后 **`tts.service` 里的路径 + `.env` 里的 `TTS_CACHE_DIR` 都要同步改**。

传输方式看你的通道：`scp -r 发布包/tts pi@<地址>:/home/pi/robot/`，或 U 盘。

## 5. 检查 `.env`（只剩 1 个值要上机填）

`.env` **已经在包里了**，不用创建。解包后只需：

```bash
cd /home/pi/robot/tts
chmod 600 .env     # zip 里已写 0600，个别解包工具会丢权限
cat .env           # 确认 MIMO_API_KEY 有值、TTS_CACHE_DIR 是绝对路径
```

里面三行是这样（Key 是脚本从本机带过来的）：

```
MIMO_API_KEY=sk-...                                  ← 已填好
TTS_CACHE_DIR=/home/pi/robot/tts/.tts_cache          ← 已填好（绝对路径）
#TTS_ALSA_DEVICE=plughw:CARD=Device,DEV=0            ← 唯一要你上机填的，见下
```

### ★ 只剩 `TTS_ALSA_DEVICE` 要上机拿

**留空也能跑**（代码会按顺序自动探测，一般能落到 USB 声卡）。
只有当"没声音"或"声卡选错"时才需要显式填。拿值的方法：

```bash
aplay -l
```

典型输出：

```
card 0: Headphones [bcm2835 Headphones], device 0    ← 板载 3.5mm（PWM，底噪大，不用）
card 1: Device [USB Audio Device], device 0          ← USB 音箱（用这个）
```

然后取消注释写成 **`plughw:CARD=<名字>,DEV=0`**（用**名字**，不是 `card 1` 那个编号）：

```
TTS_ALSA_DEVICE=plughw:CARD=Device,DEV=0
```

两个必须记住的点：

- **`plughw:` 不能写成 `hw:`**。`hw:` 是直连硬件，只接受设备原生采样率（44100/48000），
  而云端音频是 **24000Hz** → 直接报 `Sample format not available`。
  `plughw:` 会自动重采样。
- **用 CARD 名字，不要用编号**。USB 插拔 / 重启会改变 card 编号（0 变 1），名字是稳定的。

> 可选优化：让李鑫在 `/boot/config.txt` 里加 `dtparam=audio=off` 关掉板载音频，
> USB 声卡就稳定成为 card 0，顺带省电。**不做也能跑。**

> 插着 USB 音箱重启一次再确认：如果换了 USB 口 / 换设备后没声音，
> 先怀疑是编号漂移 —— 用 CARD 名字就是为了避开这个。

## 7. Windows → Pi 的四个坑（都会真实绊到你）

| 坑 | 现象 | 处理 |
|---|---|---|
| **`.env` 放错位置** | 报「Key 未配置」，但文件里明明有 | 移到与 `tts.py` 同级：`/home/pi/robot/tts/.env` |
| **换行符 CRLF** | `./selftest.sh` 报 ``\r': command not found`` | 在 Pi 上执行 `sed -i 's/\r$//' *.sh`，用 U 盘/FTP 传时尤其容易发生 |
| **不在 audio 组** | `Permission denied`，且报错位置误导 | `sudo usermod -aG audio pi`，然后**重新登录**（不是重启服务） |
| **`.env` 带了 BOM / CRLF** | Key 读取失败或末尾多一个 `\r` | 本次包里的 `.env` 由脚本生成，**已按无 BOM + LF 写出**；若你手工改过，用 `nano` 在 Pi 上重写一遍最稳 |
