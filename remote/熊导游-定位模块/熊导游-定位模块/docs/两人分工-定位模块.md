## 一、切分原则：按「室外链路 / 室内链路 + 决策层」切，不按"前后端"切

❌ **不要这样切**：A 写"硬件读取"、B 写"业务逻辑" —— B 会全程等 A 的数据，A 成为唯一瓶颈。

✅ **要这样切**：两条链路物理上互不依赖（一个插 USB 串口，一个扫蓝牙），各自能独立跑通、独立自测。

| | **A：室外链路 + 对外契约口径** | **B：室内链路 + 决策层 + 工程质量** |
|---|---|---|
| 一句话 | 把天上的卫星变成"你在 XX 景点" | 把展位里的信标变成"你在几号展位"，并决定用哪个 |
| 核心文件 | `gnss.py`、`geocode.py` | `ble_scan.py`、`switch.py`、`location.py` |
| 外部依赖 | 高德 API Key（**要个人认证，审核可能 1 天，D2 就去申请**） | 信标采购到货、现场布点 |
| 风险特征 | 依赖"天"（星况、天气、楼间距），**必须提前一天做** | 依赖"地"（现场布点），**只能现场当天做** |
| 谁更累 | 前期（D2–D5） | 后期（D6–D14） |

这样切的最大好处：**两个人在 D2–D5 完全不需要等对方**，而且一个人请假不阻塞另一个人。

## 三、三个内部接口（D1 冻结，其余随便改）

```python
# contract.py —— A 起草，D1 会上和 Agent 负责人一起过，你（整合者）拍板
@dataclass
class Fix:            # gnss.py → switch.py
    lat: float; lon: float
    quality: int      # GGA 第 6 字段：1=单点 2=差分 0=无效
    satellites: int
    hdop: float
    timestamp: float  # monotonic

@dataclass
class BeaconHit:      # ble_scan.py → switch.py
    uuid: str; major: int; minor: int
    rssi: int
    timestamp: float

# 对外唯一出口（冻结，不许改）
def get_location() -> dict:
    """gps | ble | none，永不抛异常，永不阻塞 > 200ms"""
```

内部三个函数（A、B 各出一半）：

| 函数 | 归属 | 契约 |
|---|---|---|
| `gnss.get_fix() -> Fix \| None` | A | **纯读内存缓存**，O(1)，绝不触发搜星 |
| `geocode.poi_name(lat, lon) -> str` | A | 带 sqlite 缓存 + 5s 超时；失败降级返回 `"附近"`，不抛异常 |
| `ble_scan.nearest() -> BeaconHit \| None` | B | 纯读扫描缓存，含 RSSI 滤波 |

## 四、四个必须两人一起守的设计决定

1. **`get_location()` 是非阻塞读缓存。** GPS 冷启动 30s+，绝不能按键时才去搜星 —— `gnss.py` 里跑一个常驻后台线程/`asyncio` Task 持续读串口维护最新 fix。这是分工文件里已经强调过的第一条。
2. **切换不看"有没有坐标"，看 fix 质量。** 判据：`quality in (1, 2) and satellites >= 6 and hdop <= 5` **且 30s 内有更新**。只要坐标不看质量，室内靠窗会给你一个漂到隔壁楼的点。
3. **加迟滞（hysteresis），否则演示现场会当众翻车。** 切到 `ble` 后至少保持 20s 才允许切回 `gps`。否则用户在门口来回走，mode 疯狂抖动，Agent 文案会说出前后矛盾的讲解。
4. **永不抛异常。** 任何异常 → 返回 `mode: "none"` + `confidence: 0.0`。串口拔了、蓝牙被 soft-block、高德超时，都必须走这条路。

## 六、协作规则（五条，别加码）

1. **每天群里三句话**：做完啥 / 卡在哪 / 明天干啥。不开会，15 天里会议是最贵的资源。
2. **改对方文件 = 提 PR**。自己的文件直接 push，跨边界必须让对方 review。
3. **`tests/test_switch.py` 是对外行为的唯一验收标准**（B 写 A 认）。它绿了就等于契约没破。
4. **实物只有一套，要提前占坑。** D7 之后谁要用树莓派 + GPS + 信标，前一天在群里说。A 的笔记本配 USB GPS，B 的笔记本配手机模拟信标，各自独立可跑 —— 这是两个人不互相卡的前提。
5. **不写对方模块的业务逻辑。** 对方卡住时，帮的是"看环境报错、查文档"，不是"替他写完"。

## 七、给 A 和 B 各自的三句提醒

**A：**
1. 高德 Key 要选 **"Web 服务"** 类型，申请成 Android/iOS 会直接报 `10009 USERKEY_PLAT_NOMATCH`。
2. 高德的免费额度是**按日限流**的，跑测试一定开 sqlite 缓存，否则你一天就把配额烧完（`10003 DAILY_QUERY_OVER_LIMIT`）。
3. 日志里**同时记原始 WGS84 和高德返回的 POI 名**。答辩时"我们保留了原始坐标以支持后续算法升级"是加分项。

**B：**
1. 室内 RSSI 抖动 ±10 dBm 是常态。**别做"估算距离"**，本项目只需要回答"最近的那个信标是谁" —— 做好滤波 + 最近值就赢了。
2. `beacons.yaml` 里除了 UUID→展位名，**一定要留 `tx_power_ref` 和 `rssi_threshold` 字段**，现场标定值回填，不用改代码（分工文件明确要求）。
3. 收尾前跑一遍"三个 mode"的降级演练并**截图存证**：`gps` / `ble` / 拔掉一切后 `none`。这张图比任何 PPT 都有说服力。

## 八、什么时候该停止分工

出现下面任一情况，立刻合流一起做，不要各写各的：
- D6 三种 mode 用例没全绿；
- 两个人的 `get_location()` 返回值对不上；
- D10 联调时全链路耗时 > 8s（分工文件目标是 ≤3s）；
- 有人连续两天卡在同一个问题上 —— 15 天里"两个人一起啃半天"永远优于"一个人硬扛三天"。
