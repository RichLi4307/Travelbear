## 2. 接口契约 ★ 最重要的一节

### 调用方式

```python
from location import get_location, start

start()                  # 主程序启动时调一次，把串口和蓝牙扫起来
...
loc = get_location()     # 按键时调
```

**就这两个函数。** 其他都是内部实现，可以随便重构，不影响你。

### 返回值

```python
{
    "mode": "gps" | "ble" | "none",
    "poi_name": str,        # ← 你要的就是这个，直接喂给 LLM
    "lat": float | None,    # WGS84 原始坐标，调试用
    "lon": float | None,
    "beacon_id": str | None,
    "confidence": float,    # 0~1
    "timestamp": str,       # "2026-09-16T20:52:53"
}
```

### 两条硬承诺

1. **永不抛异常。** 任何意外都返回 `mode="none"`。你可以无脑调，不用包 `try/except`。
2. **永不阻塞。** 只读内存缓存，实测 **< 5ms**。直接在按键回调里同步调，不会卡住 UI。

### `confidence` 怎么用（别忽略这个）

| 值 | 含义 | 建议动作 |
|---|---|---|
| **0.95** | 命中了景区内的具体点位（如"陈毅广场"） | 正常讲解，可以讲得很具体 |
| **0.85** | 只命中景区（如"外滩"） | 正常讲解，但别说"你正站在某某点" |
| **0.70** | 在线反解的结果，或室内信标 | 可以讲，语气保守一点 |
| **0.50** | **只有坐标，认不出地方**（`poi_name` = "当前位置附近"） | **别触发播报**，会说出废话 |
| **0.00** | `mode="none"`，定位不可用 | 走降级逻辑（提示用户、播通用内容） |

**一句话：`confidence < 0.5` 就别开口。**

### `mode` 怎么用

| mode | 什么时候 | 你要做什么 |
|---|---|---|
| `gps` | 室外，有卫星定位 | 用 `poi_name` |
| `ble` | 室内，扫到信标了 | 用 `poi_name`（展位名） |
| `none` | 都没有 | 别崩，说句"我现在认不出位置"之类的兜底话 |

## 3. Agent 怎么接进去

### 最小可用的接法

```python
from location import get_location, start

def main():
    start()                       # ← 一定要在启动时调，原因见下
    while True:
        wait_for_button()         # GPIO 按键
        loc = get_location()      # 非阻塞，< 5ms
        prompt = build_prompt(loc) # 把 loc["poi_name"] 拼进提示词
        text = call_llm(prompt)
        speak(text)

def build_prompt(loc):
    if loc["mode"] == "none":
        return "游客现在位置不明，请说一段不依赖位置的通用讲解。"
    if loc["confidence"] < 0.5:
        return "游客在某个地方但认不出具体名称，请说一段不依赖地名的引导语。"
    return f"游客现在在【{loc['poi_name']}】，请讲解这里。"
```

### ⚠️ 为什么 `start()` 必须显式调

定位模块**从开机起就在后台读串口、扫蓝牙**。`start()` 就是把这两个后台线程拉起来。

如果你不调 `start()`，第一次 `get_location()` 会兜底替你调 —— **但那时候线程刚起步，
头几秒拿不到数据，会返回 `mode="none"`**。所以：

> **在 Agent 主程序启动时调一次 `start()`，之后就随便调 `get_location()`。**

### 可选：做"走进景区自动播报"

不用改定位模块。你的模块**一直在算**，走进外滩那一刻 `poi_name` 就变了。Agent 层加个监听即可：

```python
last_name = None
while True:
    loc = get_location()
    if loc["poi_name"] != last_name and loc["confidence"] >= 0.5:
        last_name = loc["poi_name"]
        announce(loc["poi_name"])       # 进入新景区，主动播报
    time.sleep(1.5)
```

**关键点**：一定要用 `confidence >= 0.5` 过滤，否则"只有坐标认不出地方"也会触发播报。

## 4. 坐标配置怎么改

配置文件在 `location/` 下，两个：

| 文件 | 管什么 | 什么时候改 |
|---|---|---|
| `scenic_areas.yaml` | 景区围栏 + 景区内点位 | 换地点、调半径 |
| `beacons.yaml` | 信标 UUID → 展位名 | 现场布信标之后 |

### 🔴 坐标系铁律

| 谁 | 用什么坐标系 |
|---|---|
| **GNSS 模块输出** | **WGS84** |
| `scenic_areas.yaml` 里的值 | **WGS84**（除非标了 `coord: gcj02`） |
| 高德 / 腾讯 / 几乎所有国内地图 App 显示的坐标 | **GCJ-02（火星坐标）** |

**两者在中国境内相差 300~600m（上海实测 480m）。**

- 景区半径 800~1500m，偏 400m 还勉强能忍
- **点位半径只有 40~80m，偏 400m 就永远进不了圈**

### 三种取坐标的办法（推荐度从高到低）

**① 现场实测（最准）**

```bash
python location/tools/nmea_recorder.py --port COM5 --pick
```

站在目标位置别动，采 20 秒**取中位数**，直接打印能粘进 yaml 的坐标。
它还会报离散度，**>15m 说明星况不好，换个开阔位置重来**。

**② 用高德 POI 搜索自动填（现在是这么做的）**

```bash
$env:AMAP_WEB_KEY="你的key"
python location/tools/amap_fill_spots.py            # 演练，只对比不改文件
python location/tools/amap_fill_spots.py --write    # 真写（先备份 .bak）
```

⚠️ 注意两点：
- 点位名里**括号中的补充说明要去掉**才能搜准。「陈毅广场（南京东路口）」直接搜会跑到 1km 外，
  工具会自动去掉括号再搜
- 高德给的点可能是**整个区域的质心**，不一定是你想让人站的入口。**写完必须去现场走一遍确认**

**③ 直接从高德拾取器复制**

给那条配置加一行 `coord: gcj02`，加载时会自动折算成 WGS84：

```yaml
      - name: "泮池"
        lat: 31.317800
        lon: 121.396200
        coord: gcj02      # ← 从高德拾取器粘的坐标必须写这个
        radius_m: 45
```

### 改完必须复查

```bash
python -m pytest -q tests/test_location_config.py   # 11 条配置检查
```

它会抓这几类错（都是真发生过的）：

- **点位跑到景区围栏外面** —— 那样永远不可能触发（外滩的十六铺码头就犯过这个，圆心偏北 1023m > 半径 900m）
- 经纬度写反
- 两个景区圆心重合
- 点位重名

### 半径怎么定

| | 怎么算 | 参考值 |
|---|---|---|
| 景区 `radius_m` | 圆心到最远边界的距离 | 校园 900~1200m；外滩这种带状区域取两端点的中点，半径 ≈ 半长 |
| 点位 `radius_m` | 你希望"站多近才算到了" | 40~80m。太小走到跟前也不触发；太大相邻点位抢话 |

**实时调半径的工具**：

```bash
python location/tools/where_am_i.py --port COM5
```

每秒刷新：你在哪、离每个景区/点位多远、最终会被判成什么。**改完 yaml 下一秒生效，不用重启。**

站在点位正中记一个距离、走到触发边界再记一个，`radius_m` 取偏保守的中间值。

## 5. 排查表：现象 → 原因 → 动作

**这张表是这份文档里最值钱的部分。** 按现象查。

### GPS 相关

| 现象 | 最可能的原因 | 怎么办 |
|---|---|---|
| `mode` 一直是 `none` | 串口没打开 | `python -c "import serial.tools.list_ports as p; [print(x.device, x.description) for x in p.comports()]"` 确认端口名 |
| 同上 | Linux 权限 | `sudo usermod -aG dialout $USER`，**然后重新登录**（不重登不生效） |
| 同上 | 线序接反 | 模块 TX → 转接板 RX，交叉接 |
| 同上 | 天线没接/朝向不对 | 有源天线要朝天，别贴金属和人体；拿到窗外 |
| 冷启动很慢（30s~2min） | 正常 | 策略就是后台常驻搜星；**千万别在按键时才启动** |
| 数据断续丢包 | 用了 GPIO UART | 树莓派 4B 的 GPIO 真串口被板载蓝牙占着，你在 `/dev/ttyS0` 拿到的是 mini UART，波特率跟着 CPU 频率漂。**改走 USB 串口 `/dev/ttyUSB0`** |
| `poi_name` = "当前位置附近" | 有坐标但不在任何围栏里，也没配高德 | 正常兜底。要么把地点写进 `scenic_areas.yaml`，要么配 `AMAP_WEB_KEY` |
| 景区名对，但不报点位 | 星数不够 | 点位级要求 ≥6 星且 HDOP ≤5；景区级只要 ≥4 星。**这是故意的**——精度不够时只报景区，不瞎编点位 |

### 蓝牙 / 信标相关

| 现象 | 最可能的原因 | 怎么办 |
|---|---|---|
| 一个设备都扫不到 | 蓝牙被 soft-block | `rfkill unblock bluetooth` |
| 扫得到设备，扫不到信标 | 信标不是 iBeacon | 用 `python location/tools/ble_probe.py --raw` 看原始广播字节。Eddystone / 私有协议扫不出来 |
| 同上 | 信标没开机 | 很多成品信标要按一下才开始广播 |
| 信标一直在阈值外 | RSSI 阈值定太高 | `python location/tools/beacon_calibrate.py` 现场看实时值，回填 `rssi_threshold`；**同时用厂商 App 把 TX Power 调小** |
| 隔壁展位也在触发 | 半径太大 / TX Power 太大 | 优先调小 TX Power（物理隔离），其次收紧 `rssi_threshold` |

### 高德相关

| 现象 | 错误码 | 怎么办 |
|---|---|---|
| 报 `USERKEY_PLAT_NOMATCH` | 10009 | **Key 类型选错了**，要选「Web服务」，不是 Android/iOS/JS |
| 报 `INVALID_USER_KEY` | 10001 | Key 不对或过期 |
| 报 `DAILY_QUERY_OVER_LIMIT` | 10003 | 日配额用完，第二天 0:00 恢复。本地围栏照常工作 |
| 报 `CUQPS_HAS_EXCEEDED_THE_LIMIT` | 10021 | 请求太频。`tools/amap_fill_spots.py` 里 `MIN_INTERVAL_S` 调大 |
| 查询结果驴唇不对马嘴 | — | **坐标系没折算**。发出去的必须是 GCJ-02，代码里已经做了；如果改过 `geocode.py` 要复查 |
| 报 `INVALID_USER_IP` | 10005 | 控制台配了 IP 白名单，把你的出口 IP 加进去或清空白名单 |

体检工具：`python location/tools/amap_check.py`（需要 `AMAP_WEB_KEY` 环境变量）

### 行为调参

| 现象 | 改哪 |
|---|---|
| 在景区边界来回走，地名反复跳 | `contract.py` 的 `GEOFENCE_EXIT_RATIO`（默认 1.15，调大更粘） |
| 门口进进出出，gps/ble 疯狂切换 | `contract.py` 的 `SWITCH_HOLD_S`（默认 20s，调大更稳） |
| 旧定位用得太久（走出景区还报老地方） | `contract.py` 的 `FIX_MAX_AGE_S`（默认 30s，调小更灵敏） |
| 室内还想报点位 | 不用改。点位级要求 ≥6 星，室内天然达不到，会自动只报景区或转蓝牙 |

## 6. 上树莓派

```bash
sudo usermod -aG dialout $USER      # 串口免 sudo（之后要重新登录）
rfkill unblock bluetooth            # 板载蓝牙常被 soft-block
sudo systemctl enable bluetooth
```

环境变量（写进 systemd 的 `EnvironmentFile` 或 `/etc/default/`）：

```bash
GNSS_PORT=/dev/ttyUSB0
AMAP_WEB_KEY=...                    # 可选
```

### 🔴 树莓派 4B 的串口坑（别再踩）

- GPIO14/15 的**真串口（PL011）默认被板载蓝牙占用**
- 你在 `/dev/ttyS0` 拿到的是 mini UART，波特率跟着 CPU 频率漂 → **GPS 数据断续丢包**
- 想抢回 PL011 要加 `dtoverlay=disable-bt` —— **但那样板载蓝牙就没了，BLE 扫描也没了**

**所以：GPS 走 USB 串口（`/dev/ttyUSB0`），板载蓝牙原样留给 bleak。不要动 `config.txt`。**

（树莓派 5 没这个问题，无线模块走 PCIe 不占 UART。）

### 验证清单

- [ ] `ls -l /dev/ttyUSB*` 出现设备节点
- [ ] `python -c "from location import get_location; print(get_location())"` 在户外返回 `mode="gps"`
- [ ] 拔掉 GPS，返回 `mode="none"`，**不报错**
- [ ] `python location/tools/ble_probe.py` 能扫到信标
- [ ] 室内信标触发时返回 `mode="ble"` + 正确展位名
- [ ] systemd 开机自启，重启后仍能工作

## 7. 已知限制与未完成

### 硬件到货前测不了的

| 项目 | 卡在哪 |
|---|---|
| 真实串口读 NMEA | 等 NEO-M8N 到货 |
| 现场半径标定 | 同上 |
| 真实信标参数 | 等信标到货 |

### 软件层面的已知限制

- **圆形围栏对带状区域有局限**：外滩半径 900m 会跨过黄浦江，站陆家嘴一侧也会判成"外滩"。要精确得用多边形围栏（单人版明确不做）
- **高德给的点可能是质心**：比如静安公园返回的是"中心湖"，不一定是你要人站的入口
- **不做三点定位**：室内只取"最近的那个信标"，不做距离估算。RSSI 抖动 ±10dBm 是常态，距离估算在这个场景是负收益
- **不做轨迹平滑 / 卡尔曼滤波**：围栏判定不需要
- **点位级需要 6 颗星**：树荫、密集楼间可能只能报景区级，报不出点位名

### 明确不做（单人版的时间取舍）

- ❌ 多边形围栏
- ❌ RSSI 距离估算 / 三点定位
- ❌ GPS 轨迹平滑
- ❌ POI 二级分类（景点/餐厅/公交站）
- ⏳ SIM7600 4G HAT 一体化（赛后方向）
- ⏳ 景区内导航 / 路径引导

## 8. 踩过的坑（别人别再踩一遍）

这几个都是**测出来**或**踩出来**的，不是假设：

1. **高德 API 的输入必须是 GCJ-02。** 直接把 GNSS 的 WGS84 发出去，落点偏 480m —— 表现为站在外滩查出「微来美上海芮雅门诊部」。
   （`docs/分工5-定位模块.md` 里写的"勿自行偏移"是错的，它把输入和输出坐标系搞混了。）
2. **`pynmea2` 的 GGA 里字段叫 `horizontal_dil`，不是 `hdop`。** 写错会抛 `AttributeError`，而且不在常规异常捕获范围内，会让 GPS 一个坐标都解不出来。
3. **点位坐标改完必须复查"是否在景区围栏内"。** 外滩的十六铺码头曾经距圆心 1023m 而半径只有 900m —— 站在那儿按按钮永远只会说"当前位置附近"。现在有测试守着。
4. **高德个人 Key 的 QPS 很低**，连续请求会报 `10021`。批量请求要加间隔。
5. **点位名带括号说明会让高德搜错。**「陈毅广场（南京东路口）」搜出来是 1km 外的「南京路世纪广场」，去掉括号就对了。
6. **别用 GPIO UART 接 GPS**（见第 6 节）。
7. **有些清理/安全软件会按体积删 Python 库文件**，症状是"pip 莫名其妙坏了"。用 `python tools/audit_python_env.py` 体检。

## 9. 给其他模块的约定

我交付的模块遵循这套约定，**建议你们也照做**，这样合并时不会互相踩：

1. **一个模块一个目录，自包含**：代码 + 配置 + 专用脚本 + 自己的 README
2. **测试文件名带模块前缀**：`test_location_*.py` / `test_vision_*.py` / `test_tts_*.py`。
   ⚠️ **别用 `test_contract.py`、`test_config.py` 这种通用名** —— 一合并就互相覆盖
3. **对外只暴露一个函数**，放在模块的 `__init__.py` 里
4. **永不抛异常、永不阻塞**（至少对 Agent 是这样）。Agent 不该写满屏的 `try/except`
5. **每个人必须能独立自测**：一条命令跑完全部测试，不需要别人的模块，也不需要硬件
6. **`requirements.txt` 是共享的** —— 追加自己那几行，**别覆盖**
7. **跨模块改动提 PR**，不要直接改别人的目录
