# 从 GPS 到语音播报：一次按键到底发生了什么

> 写给"对这块不太懂"的人。不用懂编程也能看完。
> 看完你会知道：三个模块各管什么、定位模块为什么不能直接给坐标、以及你到了现场要做什么。

---

## 一、先记住一句话：三个模块，管三件事

| 模块 | 管什么 | 交出去的东西 |
|---|---|---|
| **定位**（你的） | 你在**哪** | 一个**地名**："外滩的十六铺码头" |
| **识图** | 你**看到了什么** | 一句场景描述："黄浦江边的万国建筑群，江对岸是陆家嘴三件套" |
| **语音播报** | 把话**说给人听** | 一段音频，从扬声器出来 |
| **Agent** | 把上面三个**拼成人话** | 导游讲解文本 |

打个比方：**定位是"眼睛知道自己在哪"，识图是"眼睛看到了什么"，TTS 是"嘴巴"，Agent 是"脑子"。**
你的定位模块就是那只能定位的耳朵——听见自己站在哪。

**关键点：你只负责前两列里的第一行。** 你不需要碰摄像头，也不需要碰扬声器。
你只需要在别人问"现在在哪"的时候，**立刻**回答一个地名。

## 二、在外滩按下按钮，5 秒内发生的事

假设你站在陈毅广场（南京东路外滩那个口子），按下按钮：

```
t=0.0s   按钮被按下
t=0.0s   Agent 同时启动两件事（并行，不是排队）
           ├─ 问定位模块：get_location()        ← 你的模块，必须 <200ms 回答
           └─ 让摄像头拍一张照片

t=0.02s  你的模块回答（几乎瞬间，因为它一直在后台跑，不是现在才开始找卫星）：
           {
             "mode": "gps",
             "poi_name": "陈毅广场（南京东路口）",
             "lat": 31.239500,
             "lon": 121.486500,
             "beacon_id": null,
             "confidence": 0.95,
             "timestamp": "2026-09-16T14:23:01"
           }

t=3.0s   识图模块回答：{"scene": "黄浦江边的万国建筑群，江对岸是陆家嘴天际线", ...}

t=3.1s   Agent 把两句话拼起来，加上导游人设，发给大模型：
           "你是一位上海导游。游客现在在【陈毅广场（南京东路口）】，
             眼前是【黄浦江边的万国建筑群，江对岸是陆家嘴天际线】。
             请用 80 字讲一段有温度的讲解。"

t=5.0s   大模型返回讲解文本 → TTS 合成 → 扬声器开口
```

**注意 t=0.02s 那一行。** 你的模块之所以能这么快，是因为它从开机起就一直在后台盯着卫星，
按键时只是"读出上一次的结果"。这是整个定位模块最重要的一个设计，
分工文件里也专门强调过：**绝不能在按键时才去冷启动搜星**（那样要等 30 秒以上）。

## 三、你的模块为什么不直接给坐标？

因为坐标对"讲解"这件事毫无用处。

```
如果交出去的是坐标：  "游客现在在 31.239500, 121.486500"
大模型会写出来：      "您正站在北纬31.2395度、东经121.4865度……"   ← 没有人话，评委也不会觉得惊艳

如果交出去的是地名：  "游客现在在 陈毅广场（南京东路口）"
大模型会写出来：      "您现在站的地方，是老上海人说的'外滩的心脏'……"   ← 这才是导游
```

所以你的交付物是**位置语义**，坐标只是中间产物。
这也是为什么你的返回值里既有 `poi_name`（给人看的）又有 `lat`/`lon`（给调试看的）。

## 四、从坐标到地名，中间发生了什么

你的模块内部有三层，从上往下试：

```
GNSS 模块给出坐标 (WGS84)
   │
   ├─ 第 1 层【本地围栏·点位】  你站的这个圈，属于配置里的哪个"点位"？
   │      → "陈毅广场（南京东路口）"      可信度 0.95      耗时 0ms
   │
   ├─ 第 2 层【本地围栏·景区】  不属于任何点位，但在哪个景区的大圈里？
   │      → "外滩"                        可信度 0.85      耗时 0ms
   │
   ├─ 第 3 层【高德在线反解】   两个本地圈都没命中（去了个陌生地方）
   │      → "XX公园北门"                  可信度 0.70      耗时 0.3~2s（后台补抓）
   │
   └─ 第 4 层【兜底】           有坐标但认不出地方
          → "当前位置附近"                可信度 0.50

如果 GPS 完全没有效定位（比如你在室内）
   → 转去问蓝牙信标 → 都没有 → mode="none"，地名"定位不可用"
```

**"本地围栏"就是一张写死的坐标表**，长这样（`location/scenic_areas.yaml`）：

```yaml
- name: "外滩"                 # 景区名，半径 900m 的大圈
  lat: 31.240000
  lon: 121.487000
  radius_m: 900
  spots:                       # 大圈里的小圈
    - name: "陈毅广场（南京东路口）"
      lat: 31.239500
      lon: 121.486500
      radius_m: 60             # 站进这个 60m 的圈，就说"陈毅广场"
```

**判定就是算距离**：手机地图上看到的"我离目标 42 米"，
在程序里就是一行距离公式。你站在哪个圈里，就报哪个名字。
点在两个圈重叠处时，**圈小的赢**（更具体）。

## 五、三个"为什么"（这几个决定都是有代价的取舍）

### 为什么本地围栏做主力，高德只做兜底？

| | 本地围栏 | 高德在线反解 |
|---|---|---|
| 耗时 | 0 毫秒 | 0.3~2 秒（还可能超时） |
| 花钱 | 免费无限 | 按日限流，用超了要等第二天 |
| 断网 | 照常工作 | **直接失效** |
| 覆盖 | 只有你写进去的地方 | 全国任意地点 |

演示当天如果现场 WiFi 抽风，只靠高德的方案会当场哑掉；本地围栏完全不受影响。
所以：**常去的地方写进配置（快、稳、免费），陌生地方才问高德（慢、但覆盖全）。**
两者是互补，不是二选一。

### 为什么"景区"和"点位"要用两档精度门槛？

- 外滩的圈半径 **900 米**：GPS 误差 10 米根本无所谓，随便判。
- 陈毅广场的圈半径 **60 米**：GPS 误差 30 米就可能判错圈，必须卡精度。

如果只有一个门槛，就会出现两种翻车：门槛太松 → 在泮池旁边却说"你在图书馆"；
门槛太严 → 树荫下只有 4 颗星时，连"你在外滩"都说不出来，直接掉到"定位不可用"。

所以代码里分了两档：**星数够判景区就先报景区名，星数够多才允许报具体点位。**
实现在 `location/contract.py` 的 `is_usable()`（宽）和 `is_precise()`（严）。

### 为什么要有"迟滞"？

两个场景：

1. **在景区边界来回走**。你在外滩边界的马路上反复横跳，如果边界是一个硬线，
   地名会"外滩→未知→外滩→未知"地跳，Agent 就会说出前后矛盾的讲解。
   → 解决：走出围栏还要再多走 **15%** 才算真的离开。
2. **在门口进进出出**。室内有信标、室外有 GPS，门口来回走会疯狂切换模式。
   → 解决：切换后 **20 秒内**不许切回去，先稳住。

这两个数字都在 `location/contract.py` 顶部，现场觉得太灵敏/太迟钝就改这里。

## 六、坐标系：一个能吃掉你一整天的坑

**中国的地图有两套"方言"：**

| | 谁在用 | 说明 |
|---|---|---|
| **WGS84** | GNSS 模块、OpenStreetMap | 卫星原始坐标，**你的模块输出的就是这个** |
| **GCJ-02**（火星坐标） | 高德、腾讯、绝大部分国内地图 App | 国家要求加密偏移过的坐标 |

**同一个地点，两套坐标在中国境内相差 300~600 米**（上海实测 **~480 米**）。

翻译成人话：你在高德地图上长按"外滩"，复制出来的坐标，
**直接粘进你的配置文件是错的** —— 会偏出去半条街。

- 景区圈半径 900 米，偏 400 米还能勉强罩住（但边界就不可信了）；
- 点位圈半径 60 米，偏 400 米就**永远不可能进去**，你会以为是自己代码写错了。

**两个正确做法：**
1. **推荐**：拿你自己的 GNSS 模块站在现场实测，`python location/tools/nmea_recorder.py --pick`，
   它采 20 秒取中位数，打印出来的坐标可以直接用。
2. 从高德复制来的坐标，给那条配置加一行 `coord: gcj02`，程序加载时会自动折算成 WGS84。

### ⚠️ 还有一个方向要记清：调高德 API 的时候

| | 方向 |
|---|---|
| 我们的 GNSS 模块给出来的 | **WGS84** |
| 高德接口**期望输入**的 | **GCJ-02** |
| 所以发请求之前 | **必须自己折算**（`location/geocode.py` 里已经做了） |
| 高德**返回**的坐标 | GCJ-02 —— 但我们只取地名不取坐标，所以不用管 |

**这不是可有可无的优化。** 我用真实 Key 实测过：不折算，站在外滩查出来的是
「微来美上海芮雅门诊部」（一栋办公楼）；折算之后才对，是「外滩-观景大道」。

> ⚠️ `docs/分工5-定位模块.md` 里写的"调用时直接用其 API 即可，**勿自行偏移**"是**错的** ——
> 它把"输入坐标系"和"输出坐标系"混为一谈了。输出确实不用管，但输入必须折算。

想自己验证，跑这个（需要 `AMAP_WEB_KEY` 环境变量）：

```bash
export AMAP_WEB_KEY=你的key          # PowerShell: $env:AMAP_WEB_KEY="你的key"
python location/tools/amap_check.py
```

它会把"发 WGS84"和"发 GCJ-02"两个结果并排打出来，偏移量直接量给你看。
顺便还会拿高德反过来核对 `scenic_areas.yaml` 里的坐标填得对不对。

## 七、你到现场要做的三件事

### 1. 取点（每个点位约 30 秒）

站在你想触发讲解的位置，别动，跑：

```bash
python location/tools/nmea_recorder.py --port COM3 --pick
```

等 20 秒，它打印一段能直接粘进 `scenic_areas.yaml` 的坐标。
**如果它说"离散度 >15m"，说明星况不好，换个开阔位置重来** —— 别将就。

### 2. 调半径（边走边看）

```bash
python location/tools/where_am_i.py --port COM3
```

屏幕上每秒刷新一次：

```
当前位置   31.239512, 121.486480
定位质量   quality=1  sats=9  hdop=0.9
判定资格   景区级=OK  点位级=OK

── 景区 ──────────────────────────────────────────────
  ✔  外滩                    距中心      74m / 半径   900m  ← 当前景区
     静安寺                  距中心    6234m / 半径   400m
     ...

── 外滩 的点位 ───────────────────────────────────────
  ✔ 命中  陈毅广场（南京东路口）  距中心      38m / 半径    60m
          外白渡桥              距中心     601m / 半径    60m

── get_location() 会返回 ─────────────────────────────
  mode=gps  poi_name=「陈毅广场（南京东路口）」  confidence=0.95
```

**站在点位正中记一个距离，走到你希望触发的边界再记一个距离，
把 `radius_m` 设在这两个值中间偏保守的位置。** 改完 yaml，屏幕下一秒就生效，不用重启。

### 3. 验三种模式

| 场景 | 期望结果 |
|---|---|
| 户外、天空开阔 | `mode="gps"`，`poi_name` 是景区名或点位名 |
| 走进室内 / 拔掉 GPS | `mode="ble"`，`poi_name` 是信标对应的展位名 |
| 什么都没有 | `mode="none"`，`poi_name="定位不可用"`，**不报错、不卡住** |

第三行是硬要求。评委看的就是"翻车了会不会崩"，而不是"顺利时有多顺"。

## 八、三个常见误解

**❌ "手机地图上显示的坐标就是我的坐标。"**
手机地图显示的是 GCJ-02（火星坐标），和模块输出差 300~600 米。别拿它当基准。

**❌ "室内也能靠 GPS。"**
GPS 信号穿不过屋顶。室内必须靠蓝牙信标（或者 WiFi 定位）。
这也是为什么你的模块是"双模"——室外 GPS、室内 BLE。室内 GPS 的表现是：
`quality=0`、星数掉到 2~3，然后你的模块自动降级去扫信标。

**❌ "想让它一进景区就自动播报，得改定位模块。"**
不用改。你的模块**从开机起就一直在算**，走进外滩的那一刻，`get_location()` 的
`poi_name` 就已经从"当前位置附近"变成"外滩"了。

要做"自动播报"，是 **Agent 层加一个监听**：
每隔一两秒问一次 `get_location()`，发现 `poi_name` 变了、或者 `mode` 从 `none` 变成 `gps`，
就触发一次播报。**这是 Agent 负责人的活，你只要保证随时问他都能立刻答。**

如果他想做这个，你可以顺手告诉他一句：
> "`poi_name` 变化就是进入新景区的信号，但记得用 `confidence` 过滤 ——
> 低于 0.5 的（只有坐标认不出地方）别触发播报，不然会说废话。"
